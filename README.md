# Web Serial Tool

> 网页串口调试工具 - 零安装、云端同步、远程协作

[![License](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)
[![Node.js](https://img.shields.io/badge/node-%3E%3D18.0.0-brightgreen.svg)](https://nodejs.org/)
[![Chrome](https://img.shields.io/badge/chrome-89%2B-blue.svg)](https://www.google.com/chrome/)

一个基于 Web Serial API 的浏览器原生串口调试工具，支持配置云端同步和实时远程协作。

## ✨ 核心特性

- 🔌 **零安装** - Web 端浏览器打开即用，无需下载
- 📂 **多项目管理** - 支持多项目创建和管理，配置云端同步
- ⚡ **测试库** - 测试库、测试单、测试用例管理，支持变量和校验码
- 📊 **数据分析** - 实时统计、发送接收配对、数据导出
- 👥 **远程协作** - 会话共享（邀请码模式）、智能桥接（连接码模式）
- ☁️ **云端同步** - 项目、配置、发送历史跨设备自动同步
- 🎨 **现代化 UI** - 响应式设计，浅/深色主题，国际化支持（中英文）
- 📚 **Wiki 知识库** - 帮助文档、使用教程、FAQ
- 🔧 **管理员后台** - 用户管理、系统监控、日志查看

> 📝 **说明**：本文档已根据实际代码实现更新，反映当前版本的实际功能。

## 🚀 快速开始

### 环境要求

- **浏览器**: Chrome 89+ 或 Edge 89+（支持 Web Serial API）
- **Node.js**: 18.0.0+
- **操作系统**: Windows 10+ / macOS 11+ / Linux
- **数据库**（生产环境）: PostgreSQL 14+

### 安装与运行（本地开发）

```bash
# 克隆项目
git clone https://github.com/your-username/web-serial.git
cd web-serial

# 安装后端依赖（终端 1）
cd backend
npm install
npm run dev
# 后端服务运行在 http://localhost:3001

# 安装前端依赖（终端 2）
cd frontend
npm install
npm run dev
# 前端服务运行在 http://localhost:5173

# 打开浏览器访问前端地址
# 默认信令地址：ws://localhost:3001/ws/signal?room=demo
```


### 远程协作

支持两种远程协作模式：

#### 模式1：会话共享（邀请码模式）
发起者连接设备后创建会话，协作者通过邀请码加入：

**基础流程**：
1. 发起者连接设备，点击"发起远程会话"
2. 生成 6 位数字邀请码（如：123456）
3. 协作者输入邀请码加入会话
4. 所有参与者实时查看相同的串口数据流

**发送权控制**：
- 协作者连接后，**默认抢占发送权**，可以立即发送数据
- 发起者需要点击"抢占发送权"才能重新获取控制
- 双方可以随时抢占发送权，实现轮流操作
- 当前拥有发送权的用户可以发送数据，其他用户发送区禁用

**适用场景**：
- 远程技术支持（协作者快速接管控制）
- 协作调试（双方轮流操作）
- 教学演示（讲师和学员切换控制）

#### 模式2：智能桥接（连接码模式）⭐
智能检测设备连接状态，自动调整交互模式，支持有设备/无设备的灵活组合：

**基础流程**：
1. 用户A和用户B创建桥接连接（生成/输入连接码）
2. **自动检测**：系统检测双方是否连接物理设备
3. **智能适应**：根据设备连接状态自动调整UI和数据流

**🔄 四种自适应场景**：

**场景1：双方都有设备（设备桥接）**
```
设备A ⟷ 用户A（监控） ⟷ 网络 ⟷ 用户B（监控） ⟷ 设备B
```
- 双方发送区禁用，只能监控
- 设备间透明通信

**场景2：A有设备，B无设备（远程访问）**
```
设备A ⟷ 用户A（监控） ⟷ 网络 ⟷ 用户B（可发送）
```
- A只能监控，B可以手动发送命令到设备A
- 适用于远程技术支持、教学演示

**场景3：A无设备，B有设备（远程访问）**
```
用户A（可发送） ⟷ 网络 ⟷ 用户B（监控） ⟷ 设备B
```
- A可以手动发送命令到设备B，B只能监控
- 适用于远程设备控制

**场景4：双方都无设备（纯软件测试）** 🧪
```
用户A（可发送） ⟷ 网络 ⟷ 用户B（可发送）
```
- 双方都可以手动发送/接收数据
- **完美解决无硬件测试问题**
- 适用于产品测试、协议调试、教学演示

**应用场景**：
- 🔧 远程技术支持（技术人员远程调试客户设备）
- 📚 教学演示（无需硬件，演示串口通信）
- 🧪 产品测试（双人协作，无需任何硬件）
- 🌉 设备桥接（连接物理隔离的两个设备）

默认信令地址：`ws://localhost:3001/ws/signal?room=<room-id>`

## 🏗️ 技术栈

### Web 端（主力产品）
- **前端**: React 18 + TypeScript + Vite + Tailwind CSS
- **串口**: Web Serial API
- **实时通信**: WebSocket（信令服务器）
- **认证**: JWT（邮箱注册/登录）
- **国际化**: react-i18next（支持中英文）

### 桌面端（增强版本，第三阶段）
- **框架**: Electron（推荐）或 Tauri
- **串口**: Node.js serialport（原生访问）
- **代码复用**: ~80% 复用 Web 端代码
- **平台**: Windows/macOS/Linux

### 移动端（辅助工具，第三阶段）
- **框架**: React Native（推荐）或 Flutter
- **串口**: Android USB OTG（iOS 不支持）
- **代码复用**: ~60% 复用 Web 端代码
- **平台**: iOS 15+、Android 8+

### 后端服务（共享）
- **框架**: Node.js + Express + WebSocket
- **数据库**: PostgreSQL + Prisma ORM
- **认证**: JWT（邮箱注册/登录）
- **国际化**: 自定义 i18n 实现（支持中英文）

### 本地开发端口
- 前端开发服务器: `5173`
- 后端/信令服务: `3001`

### 常见问题

| 问题 | 可能原因 | 解决方案 |
|------|---------|---------|
| **浏览器无"连接设备"按钮** | 浏览器不支持 Web Serial API | 使用 Chrome 89+ 或 Edge 89+，或使用桌面端应用 |
| **无法访问串口** | 未授权 HTTPS 或非 localhost | 使用 HTTPS 或 `http://localhost` |
| **无法看到串口设备** | 系统权限未授权 | macOS: 系统设置→隐私与安全性→输入监控/USB<br>Linux: 用户需在 `dialout` 组<br>Windows: 检查设备管理器 |
| **远程协作无数据** | 邀请码错误或网络问题 | 检查邀请码、信令地址可达性、防火墙设置 |
| **文本发送乱码** | 编码格式不匹配 | 统一使用 UTF-8 编码或切换编码格式 |
| **连接频繁断开** | 设备驱动问题或权限变更 | 检查设备驱动、重新授权串口权限 |
| **数据配对不准确** | 配对时间窗口太短 | 在设置中调整配对时间窗口（默认3秒） |
| **心跳数据太多** | 未开启心跳过滤 | 在数据分析面板中开启"隐藏心跳数据" |

更多问题请查看 [运维手册](./docs/06-project-mgmt/05-运维手册.md) 或 [Wiki 文档](./docs/01-product/11-功能需求-Wiki.md)
