# 远程连接（智能桥接）

> WebSerialTool 智能桥接功能：连接两个设备或实现远程访问

---

## 功能概述

智能桥接模式允许两个用户作为桥接器，连接两个不同的设备（或一个设备），实现设备间透明通信或远程访问。系统自动检测用户的设备连接状态，动态调整交互模式，支持有设备/无设备的灵活组合。

**核心特性**：
- ✅ **智能检测**：自动检测双方是否连接物理设备
- ✅ **自适应UI**：根据设备状态动态启用/禁用发送区
- ✅ **灵活交互**：有设备的用户只能监控，无设备的用户可以手动发送
- ✅ **状态同步**：双方实时同步设备连接状态

**核心价值**：
- ✅ 支持4种自适应场景，无需切换模式
- ✅ 完美解决无硬件测试问题
- ✅ 远程技术支持场景体验极佳

---

## 四种自适应场景

### 场景1：双方都有设备（设备桥接）

**应用场景**：
- 连接物理隔离的两个设备
- 设备间透明数据传输
- 远程设备测试

**传输流程**：
```
设备A ⟷ 用户A（监控） ⟷ 网络 ⟷ 用户B（监控） ⟷ 设备B
```

**用户角色**：
- 用户是**桥接器**：负责转发两个设备间的数据
- 用户是**监控者**：可以查看数据流，但不能手动干预
- 数据转发自动完成：无需用户确认

**界面显示**：
- 双方发送区自动禁用
- 显示双方设备状态：🟢 ESP32 / 🟢 Arduino
- 显示桥接模式：设备桥接

---

### 场景2：A有设备，B无设备（远程访问）

**应用场景**：
- 远程技术支持（技术人员远程调试客户的设备）
- 远程设备控制

**传输流程**：
```
设备A ⟷ 用户A（监控） ⟷ 网络 ⟷ 用户B（可发送）
```

**用户角色**：
- 用户A（有设备）：只能监控，发送区禁用
- 用户B（无设备）：可以手动发送命令到设备A

**界面显示**：
- 用户A：发送区禁用，显示"设备桥接模式，发送区已禁用"
- 用户B：发送区启用，显示"可手动发送数据到远程设备"

---

### 场景3：A无设备，B有设备（远程访问）

**说明**：与场景2类似，角色对调。

**应用场景**：
- 远程设备访问
- 客户端控制服务器设备

---

### 场景4：双方都无设备（纯软件测试）

**应用场景**：
- 教学演示（无需硬件，演示串口通信原理）
- 产品测试（双人协作，无需任何硬件设备）
- 软件功能验证

**传输流程**：
```
用户A（可发送） ⟷ 网络 ⟷ 用户B（可发送）
```

**用户角色**：
- 双方都可以手动发送/接收数据
- 无需硬件即可测试产品功能

**界面显示**：
- 双方发送区都启用
- 显示模式：软件测试
- 提示：无设备模式，双方可自由交互

## 快速开始

### 1. 创建连接码

**用户A（发起者）**：
1. 选择是否连接物理设备（可选）
2. 点击"启用智能桥接"按钮
3. 系统生成 6 位数字连接码（如：234567）
4. 系统自动检测设备连接状态
5. 显示连接码，等待用户B连接

**连接码规则**：
- 6 位数字（000000-999999）
- 唯一性：同一时间不重复
- 有效期：桥接断开后失效
- 可重新生成

### 2. 输入连接码

**用户B（加入者）**：
1. 选择是否连接物理设备（可选）
2. 点击"启用智能桥接"按钮
3. 输入 6 位数字连接码
4. 系统自动检测设备连接状态
5. 点击"建立桥接"按钮

### 3. 建立桥接连接

**建立流程**：
1. 验证连接码有效性
2. 建立 WebRTC P2P 或 WebSocket 连接
3. **交换设备状态**：双方同步设备连接信息
4. **自适应UI**：根据设备状态调整界面
5. 显示桥接状态和模式（双设备/单设备/无设备）

## 设备状态检测

### 自动检测

**检测方式**：
- 自动检测是否调用了 `navigator.serial.requestPort()`
- 检测串口是否成功打开
- 实时监测设备连接/断开事件
- 设备状态变化时，立即通知对方并更新UI

**状态类型**：
- 🟢 **已连接设备**：物理设备已连接并打开
- 🔴 **未连接设备**：无物理设备连接

### 状态同步

**状态同步机制**：

1. **初始状态交换**
   - 建立连接时，双方交换设备状态
   - 包含：是否有设备、设备类型、设备信息

2. **状态变化通知**
   - 用户连接设备 → 立即通知对方
   - 用户断开设备 → 立即通知对方
   - 设备信息变化 → 立即通知对方

3. **UI自动调整**
   - 根据本地设备状态：启用/禁用发送区
   - 根据远程设备状态：调整显示文案和提示
   - 更新桥接模式标识（设备桥接/远程访问/软件测试）

## 数据传输

### 数据流向

**自动转发**：
- 设备数据自动转发给对方
- 对方有设备时，自动写入对方设备
- 对方无设备时，仅显示不写入

**手动发送**：
- 无设备用户可以手动发送
- 数据发送给有设备的用户
- 自动写入对方的设备

### 数据包结构

```javascript
{
  source: 'device' | 'manual',  // 来源：设备或手动
  from: 'userA' | 'userB',      // 发送者
  hasDevice: boolean,           // 发送者是否有设备
  data: Uint8Array,
  timestamp: number
}
```

## 桥接管理

### 桥接状态

**状态类型**：
- 🟢 **设备桥接**：设备A ⟷ 设备B
- 🟢 **远程访问**：用户A ⟷ 设备B
- 🟢 **软件测试**：用户A ⟷ 用户B
- 🔴 **桥接已断开**
- 🟡 **桥接连接中**

**状态显示**：
- 状态图标和文字
- 双方设备状态
- 连接模式标识
- 连接时长

### 断开桥接

**操作方式**：
1. 点击"断开桥接"按钮
2. 确认对话框（可选）
3. 通知对方
4. 清理连接状态

### 重新建立

**操作方式**：
- 重新生成连接码
- 重新输入连接码
- 快速重连（使用上次连接码）

## 使用示例

### 示例1：设备桥接

**场景**：连接两个物理隔离的 ESP32 设备

**步骤**：
1. 用户A连接设备A，创建桥接，生成连接码
2. 用户B连接设备B，输入连接码
3. 系统检测到双方都有设备，自动进入设备桥接模式
4. 设备A发送的数据自动转发到设备B
5. 设备B发送的数据自动转发到设备A

**结果**：两个设备实现透明通信，用户只能监控，不能干预。

---

### 示例2：远程技术支持

**场景**：技术人员远程调试客户的设备

**步骤**：
1. 客户（用户A）连接设备，创建桥接，生成连接码
2. 技术人员（用户B）不连接设备，输入连接码
3. 系统检测到用户A有设备，用户B无设备，自动进入远程访问模式
4. 技术人员可以发送命令到客户设备
5. 客户只能监控，看到设备响应

**结果**：技术人员可以远程控制客户设备，客户可以看到所有操作。

---

### 示例3：无硬件测试

**场景**：两个开发者协作测试串口通信协议

**步骤**：
1. 用户A不连接设备，创建桥接，生成连接码
2. 用户B不连接设备，输入连接码
3. 系统检测到双方都无设备，自动进入软件测试模式
4. 双方都可以手动发送/接收数据
5. 模拟设备通信，测试协议逻辑

**结果**：无需硬件即可测试串口通信功能，完美解决无硬件测试问题。

## 常见问题

### Q: 如何知道当前是什么模式？

**A:** 查看界面上的状态栏，会显示：
- 设备桥接：双方都有设备
- 远程访问：一方有设备，一方无设备
- 软件测试：双方都无设备

### Q: 为什么我的发送区被禁用了？

**A:** 当你有设备连接时，发送区会自动禁用，因为你是桥接器，只能监控设备间的通信。如果你需要手动发送，请断开设备连接。

### Q: 设备断开后会自动切换模式吗？

**A:** 是的。系统会实时检测设备状态变化，自动调整桥接模式和UI。设备断开后，你的发送区会自动启用。

### Q: 连接码可以重复使用吗？

**A:** 连接码在桥接断开后失效。如果需要重新建立桥接，需要重新生成或输入连接码。
