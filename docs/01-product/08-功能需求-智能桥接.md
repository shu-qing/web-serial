## 1. 功能概述

智能桥接模式（自适应）允许两个用户作为桥接器，连接两个不同的设备（或一个设备），实现设备间透明通信或远程访问。系统自动检测用户的设备连接状态，动态调整交互模式，支持有设备/无设备的灵活组合。

**核心特性**：
- ✅ **智能检测**：自动检测双方是否连接物理设备
- ✅ **自适应UI**：根据设备状态动态启用/禁用发送区
- ✅ **灵活交互**：有设备的用户只能监控，无设备的用户可以手动发送
- ✅ **状态同步**：双方实时同步设备连接状态

**核心价值**：
- ✅ 支持4种自适应场景，无需切换模式
- ✅ 完美解决无硬件测试问题
- ✅ 远程技术支持场景体验极佳

## 2. 四种自适应场景

### 2.1 场景1：双方都有设备（设备桥接）

**应用场景**：
- 连接物理隔离的两个设备
- 设备间透明数据传输
- 远程设备测试

**传输流程**：
1. 设备A发送 → 用户A监控 → 网络转发 → 用户B监控 → 写入设备B
2. 设备B发送 → 用户B监控 → 网络转发 → 用户A监控 → 写入设备A

**用户角色**：
- 用户是**桥接器**：负责转发两个设备间的数据
- 用户是**监控者**：可以查看数据流，但不能手动干预
- 数据转发自动完成：无需用户确认

**用户界面（用户A）**：
```
┌─────────────────────────────────────┐
│ 智能桥接模式 - 设备桥接              │
│ 本地: 🟢 ESP32  远程: 🟢 Arduino    │
├─────────────────────────────────────┤
│ 设备发送区（只读监控）               │
│ ┌─────────────────────────────────┐ │
│ │ [14:32:15] → Hello from A       │ │
│ └─────────────────────────────────┘ │
│ 设备接收区（只读监控）               │
│ ┌─────────────────────────────────┐ │
│ │ [14:32:17] ← Hello from B       │ │
│ └─────────────────────────────────┘ │
│ 🚫 发送区已禁用（设备桥接模式）      │
└─────────────────────────────────────┘
```

**详细需求**：
- ✅ 双方只能监控，不能手动发送
- ✅ 设备间透明通信
- ✅ 发送区自动禁用
- ✅ 显示双方设备状态

---

### 2.2 场景2：A有设备，B无设备（远程访问）

**应用场景**：
- 远程技术支持（技术人员远程调试客户的设备）
- 远程设备控制

**传输流程**：
1. 设备A发送 → 用户A监控 → 网络转发 → 用户B接收（显示）
2. 用户B手动发送 → 网络转发 → 用户A接收 → 写入设备A

**用户界面（用户B - 无设备）**：
```

```

**详细需求**：
- ✅ A只能监控，B可以手动发送命令到设备A
- ✅ 适用于远程技术支持
- ✅ 用户B的发送区启用
- ✅ 用户A的发送区禁用

## 3. 建立桥接连接

### 3.1 创建连接码

**功能描述**：用户A生成连接码，等待用户B连接

**详细流程**：
1. 用户A选择是否连接物理设备（可选）
2. 点击"启用智能桥接"按钮
3. 系统生成 6 位数字连接码（如：234567）
4. **系统检测**：检测用户A是否连接设备
5. 显示连接码，等待用户B连接

**连接码规则**：
- ✅ 6 位数字（000000-999999）
- ✅ 唯一性：同一时间不重复
- ✅ 有效期：桥接断开后失效
- ✅ 可重新生成

**界面元素**：
- 连接码显示（大号字体，便于分享）
- 复制连接码按钮
- 当前设备状态显示
- 等待连接提示

---

### 3.2 输入连接码

**功能描述**：用户B输入连接码建立桥接

**详细流程**：
1. 用户B选择是否连接物理设备（可选）
2. 点击"启用智能桥接"按钮
3. 输入 6 位数字连接码
4. **系统检测**：检测用户B是否连接设备
5. 点击"建立桥接"按钮

**详细需求**：
- ✅ 连接码输入框（6位数字）
- ✅ 自动格式化和验证
- ✅ 显示设备状态
- ✅ 建立桥接按钮

---

### 3.3 建立桥接连接

**功能描述**：建立P2P连接并同步设备状态

**详细流程**：
1. 验证连接码有效性
2. 建立 WebRTC P2P 或 WebSocket 连接
3. **交换设备状态**：双方同步设备连接信息
4. **自适应UI**：根据设备状态调整界面
5. 显示桥接状态和模式（双设备/单设备/无设备）

**详细需求**：
- ✅ 连接码验证
- ✅ P2P连接建立
- ✅ 设备状态交换
- ✅ UI自动调整
- ✅ 桥接状态显示

---

## 4. 设备状态检测

### 4.1 自动检测

**检测方式**：
- ✅ 自动检测是否调用了 `navigator.serial.requestPort()`
- ✅ 检测串口是否成功打开
- ✅ 实时监测设备连接/断开事件
- ✅ 设备状态变化时，立即通知对方并更新UI

**状态类型**：
- 🟢 **已连接设备**：物理设备已连接并打开
- 🔴 **未连接设备**：无物理设备连接

---

### 4.2 状态同步

**功能描述**：实时同步双方的设备连接状态，确保UI和数据流正确调整

**状态同步机制**：

**1. 初始状态交换**
- 建立连接时，双方交换设备状态
- 包含：是否有设备、设备类型、设备信息

**2. 状态变化通知**
- 用户连接设备 → 立即通知对方
- 用户断开设备 → 立即通知对方
- 设备信息变化 → 立即通知对方

**3. UI自动调整**
- 根据本地设备状态：启用/禁用发送区
- 根据远程设备状态：调整显示文案和提示
- 更新桥接模式标识（设备桥接/远程访问/软件测试）

**状态消息格式**：
```javascript
{
  type: 'device_status',
  hasDevice: boolean,           // 是否连接设备
  deviceInfo: {                // 设备信息（可选）
    type: 'ESP32' | 'Arduino',
    port: 'COM3',
    baudRate: 115200
  },
  timestamp: number
}
```

## 5. 动态UI调整

### 5.1 UI调整规则

**调整规则表**：

| 本地设备 | 远程设备 | 本地发送区 | 显示模式 |
|---------|---------|-----------|---------|
| ✅ 有   | ✅ 有   | 🚫 禁用   | 设备桥接 |
| ✅ 有   | ❌ 无   | 🚫 禁用   | 远程访问（被访问）|
| ❌ 无   | ✅ 有   | ✅ 启用   | 远程访问（访问中）|
| ❌ 无   | ❌ 无   | ✅ 启用   | 软件测试 |

---

### 5.2 UI元素调整

**1. 发送区**
- 有设备：禁用输入框，显示提示"设备桥接模式，发送区已禁用"
- 无设备：启用输入框，显示提示"可手动发送数据到远程"

**2. 接收区标题**
- 双设备："设备接收区（来自远程设备）"
- 单设备："远程数据区（来自用户X）"
- 无设备："接收区（来自对方）"

**3. 状态栏**
- 显示双方设备状态：🟢 ESP32 / 🔴 无设备
- 显示当前模式：设备桥接 / 远程访问 / 软件测试

## 6. 数据传输

### 6.1 数据流向

**数据包结构**：
```javascript
{
  source: 'device' | 'manual',  // 来源：设备或手动
  from: 'userA' | 'userB',      // 发送者
  hasDevice: boolean,           // 发送者是否有设备
  data: Uint8Array,
  timestamp: number
}
```

### 6.2 传输规则

**自动转发**：
- ✅ 设备数据自动转发给对方
- ✅ 对方有设备时，自动写入对方设备
- ✅ 对方无设备时，仅显示不写入

**手动发送**：
- ✅ 无设备用户可以手动发送
- ✅ 数据发送给有设备的用户
- ✅ 自动写入对方的设备

## 9. 技术实现

### 9.1 通信通道

**WebRTC P2P（优先）**：
- ✅ 低延迟（< 100ms）
- ✅ 端到端加密
- ✅ 直接传输，减少服务器负担

**WebSocket 中转（回退）**：
- ✅ WebRTC 连接失败时使用
- ✅ 服务器作为中转
- ✅ 低延迟优化（< 300ms）

---

### 9.2 数据压缩

**详细需求**：
- ✅ 文本压缩（Gzip）
- ✅ 批量发送（多个数据包合并）
- ✅ 增量更新（仅发送新增数据）

---

### 9.3 网络容错

**断线检测**：
- ✅ 心跳机制（每 5 秒 ping）
- ✅ 3 次心跳超时判定断线
- ✅ 显示网络状态：🟢 良好 / 🟡 延迟高 / 🔴 断线

**自动重连**：
- ✅ 指数退避重连（1s, 2s, 4s, 8s, 16s）
- ✅ 最多重连 10 次
- ✅ 重连成功后数据回放
- ✅ 显示重连进度

**数据完整性**：
- ✅ 序号机制防止乱序
- ✅ 断点续传
- ✅ 丢包检测和重传

## 10. 安全与隔离

### 10.1 数据隔离

**详细需求**：
- ✅ 浏览器不直接暴露串口句柄
- ✅ 仅传输字符流，不传输字节流细节
