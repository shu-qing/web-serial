## 1. 错误分类体系

### 1.1 前端错误分类

#### 1.1.1 串口连接错误

| 错误类型 | 错误码 | 说明 | 处理方式 |
|---------|--------|------|---------|
| `SERIAL_NOT_SUPPORTED` | `SERIAL_001` | 浏览器不支持 Web Serial API | 显示浏览器不支持提示，引导用户使用 Chrome/Edge |
| `SERIAL_PERMISSION_DENIED` | `SERIAL_002` | 用户拒绝串口权限 | 提示用户需要授权，提供重试按钮 |
| `SERIAL_DEVICE_NOT_FOUND` | `SERIAL_003` | 未找到串口设备 | 提示检查设备连接，提供刷新设备列表按钮 |
| `SERIAL_PORT_BUSY` | `SERIAL_004` | 串口被其他程序占用 | 提示关闭占用程序，提供重试按钮 |
| `SERIAL_CONNECTION_FAILED` | `SERIAL_005` | 连接失败（配置错误等） | 显示具体错误原因，验证配置参数 |
| `SERIAL_DISCONNECTED` | `SERIAL_006` | 连接意外断开 | 自动检测并提示重连 |
| `SERIAL_READ_ERROR` | `SERIAL_007` | 读取数据错误 | 记录错误日志，尝试恢复连接 |
| `SERIAL_WRITE_ERROR` | `SERIAL_008` | 写入数据错误 | 记录错误日志，提示检查设备状态 |

**错误处理流程**：
```
检测错误 → 记录错误日志 → 用户提示 → 提供重试/恢复选项
```

## 2. 错误处理流程

### 2.1 前端错误处理流程

```typescript
// 错误处理统一入口
class ErrorHandler {
  handle(error: Error, context: ErrorContext): void {
    // 1. 错误分类
    const errorType = this.classifyError(error)
    
    // 2. 记录错误日志
    this.logError(error, context)
    
    // 3. 根据错误类型处理
    switch (errorType) {
      case 'SERIAL_001':
        this.showBrowserNotSupported()
        break
      case 'SERIAL_002':
        this.showPermissionDenied()
        break
      case 'NET_002':
        this.retryWithBackoff(context)
        break
      case 'RTC_001':
        this.fallbackToWebSocket()
        break
      default:
        this.showGenericError(error)
    }
  }
}
```

## 3. 重试策略

### 3.1 指数退避算法

**算法描述**：
```
重连间隔 = min(initialDelay * (2 ^ attempt), maxDelay)
```

**参数配置**：

| 场景 | 初始延迟 | 最大延迟 | 最大次数 |
|------|---------|---------|---------|
| 串口重连 | 1 秒 | 30 秒 | 5 次 |
| 网络请求重试 | 0.5 秒 | 10 秒 | 3 次 |
| WebSocket 重连 | 1 秒 | 30 秒 | 10 次 |
| WebRTC 重连 | 2 秒 | 60 秒 | 3 次 |

**实现示例**：

```typescript
class RetryManager {
  private attempts = 0
  private readonly maxAttempts: number
  private readonly initialDelay: number
  private readonly maxDelay: number

  constructor(
    maxAttempts: number,
    initialDelay: number,
    maxDelay: number
  ) {
    this.maxAttempts = maxAttempts
    this.initialDelay = initialDelay
    this.maxDelay = maxDelay
  }

  async retry<T>(
    fn: () => Promise<T>,
    onRetry?: (attempt: number, delay: number) => void
  ): Promise<T> {
    while (this.attempts < this.maxAttempts) {
      try {
        return await fn()
      } catch (error) {
        this.attempts++
        
        if (this.attempts >= this.maxAttempts) {
          throw new Error(`Max retry attempts (${this.maxAttempts}) exceeded`)
        }

        const delay = Math.min(
          this.initialDelay * Math.pow(2, this.attempts - 1),
          this.maxDelay
        )

        if (onRetry) {
          onRetry(this.attempts, delay)
        }

        await this.sleep(delay)
      }
    }
    throw new Error('Retry failed')
  }

  private sleep(ms: number): Promise<void> {
    return new Promise(resolve => setTimeout(resolve, ms))
  }

  reset(): void {
    this.attempts = 0
  }
}

// 使用示例
const retryManager = new RetryManager(5, 1000, 30000)

try {
  await retryManager.retry(
    async () => {
      return await connectSerialPort(port)
    },
    (attempt, delay) => {
      console.log(`Retry attempt ${attempt} after ${delay}ms`)
      showRetryNotification(`正在重试连接... (${attempt}/5)`)
    }
  )
} catch (error) {
  showError('连接失败，请检查设备')
}
```

### 3.2 重试条件

**可重试的错误**：
- 网络超时（`NETWORK_TIMEOUT`）
- 服务器 5xx 错误（`API_ERROR_5XX`）
- WebSocket 连接断开（非正常关闭）
- 串口读取错误（`SERIAL_READ_ERROR`）

**不可重试的错误**：
- 认证失败（`UNAUTHORIZED`）
- 权限不足（`FORBIDDEN`）
- 参数验证错误（`VALIDATION_ERROR`）
- 资源不存在（`RESOURCE_NOT_FOUND`）

## 4. 降级方案

### 4.1 WebRTC → WebSocket 降级

**触发条件**：
- WebRTC 连接建立失败
- ICE 连接失败（无法建立 P2P）
- DataChannel 传输失败

**降级流程**：

```
1. 尝试 WebRTC 连接
   ↓
2. 检测连接失败
   ↓
3. 切换到 WebSocket 模式
   ↓
4. 通知用户降级状态
   ↓
5. 记录降级原因（用于优化）
```

**实现示例**：

```typescript
class RemoteSessionManager {
  private connectionMode: 'webrtc' | 'websocket' = 'webrtc'

  async establishConnection(): Promise<void> {
    try {
      // 1. 尝试 WebRTC
      await this.connectWebRTC()
      this.connectionMode = 'webrtc'
      console.log('WebRTC connection established')
    } catch (error) {
      console.warn('WebRTC connection failed, falling back to WebSocket:', error)
      
      // 2. 降级到 WebSocket
      try {
        await this.connectWebSocket()
        this.connectionMode = 'websocket'
        this.notifyUser('已切换到 WebSocket 模式（延迟可能略高）')
        this.logFallback('webrtc_to_websocket', error)
      } catch (wsError) {
        throw new Error('Both WebRTC and WebSocket connections failed')
      }
    }
  }

  private async connectWebRTC(): Promise<void> {
    const pc = new RTCPeerConnection({
      iceServers: [
        { urls: 'stun:stun.l.google.com:19302' },
        { urls: 'turn:turn.example.com:3478', username: 'user', credential: 'pass' }
      ]
    })

    // 设置超时（10 秒）
    const timeout = new Promise((_, reject) => {
      setTimeout(() => reject(new Error('WebRTC connection timeout')), 10000)
    })

    const connection = Promise.race([
      this.setupDataChannel(pc),
      timeout
    ])

    await connection
  }

  private async connectWebSocket(): Promise<void> {
    const ws = new WebSocket(`ws://localhost:3001/ws/data?session=${this.sessionId}`)
    
    return new Promise((resolve, reject) => {
      ws.onopen = () => resolve()
      ws.onerror = reject
      
      setTimeout(() => reject(new Error('WebSocket connection timeout')), 10000)
    })
  }
}
```

### 4.2 高负载限制

**触发条件**：
- 接收数据速率 > 200 KB/s
- 内存使用 > 150 MB
- 渲染帧率 < 30 FPS

**降级策略**：

| 负载情况 | 降级措施 |
|---------|---------|
| 接收速率 > 200 KB/s | 启用采样显示（每 N 条显示 1 条） |
| 内存使用 > 150 MB | 自动清理旧数据（保留最近 1000 行） |
| 帧率 < 30 FPS | 降低刷新频率（500ms 刷新一次） |

**实现示例**：

```typescript
class DataReceiver {
  private receiveBuffer: string[] = []
  private maxBufferSize = 100000
  private highLoadThreshold = 200 * 1024 // 200 KB/s

  handleData(data: string): void {
    // 检测高负载
    const receiveRate = this.calculateReceiveRate()
    
    if (receiveRate > this.highLoadThreshold) {
      // 降级：采样显示
      this.enableSampling(10) // 每 10 条显示 1 条
      this.showWarning('数据流量过大，已启用采样显示模式')
    }

    // 检测内存使用
    if (this.receiveBuffer.length > this.maxBufferSize) {
      // 自动清理最旧数据
      const keepCount = 1000
      this.receiveBuffer = this.receiveBuffer.slice(-keepCount)
      this.showNotification(`缓冲区已满，已清理旧数据（保留最近 ${keepCount} 条）`)
    }

    this.receiveBuffer.push(data)
    this.updateDisplay()
  }

  private calculateReceiveRate(): number {
    // 计算最近 1 秒的数据量
    const now = Date.now()
    const oneSecondAgo = now - 1000
    const recentData = this.receiveBuffer.filter(
      entry => entry.timestamp > oneSecondAgo
    )
    return recentData.reduce((sum, entry) => sum + entry.size, 0)
  }
}
```

### 4.3 数据缓冲

**离线缓冲**：
- 网络断开时，本地缓存待发送数据
- 网络恢复后，自动同步缓存数据
- 缓存大小限制：10 MB

**实现示例**：

```typescript
class OfflineBuffer {
  private buffer: Array<{ data: string, timestamp: number }> = []
  private maxBufferSize = 10 * 1024 * 1024 // 10 MB
  private currentSize = 0

  add(data: string): void {
    if (this.currentSize + data.length > this.maxBufferSize) {
      throw new Error('Buffer is full')
    }

    this.buffer.push({
      data,
      timestamp: Date.now()
    })
    this.currentSize += data.length
  }

  async flush(): Promise<void> {
    while (this.buffer.length > 0) {
      const item = this.buffer.shift()!
      try {
        await this.sendToServer(item.data)
        this.currentSize -= item.data.length
      } catch (error) {
        // 发送失败，重新入队
        this.buffer.unshift(item)
        throw error
      }
    }
  }
}
```

## 7. 监控与告警规则

### 7.1 错误率监控

**指标定义**：
- **错误率** = 错误请求数 / 总请求数
- **目标值**：< 1%

**告警规则**：
- **P0**：错误率 > 5%（立即告警）
- **P1**：错误率 > 2%（15 分钟内告警）
- **P2**：错误率 > 1%（1 小时内告警）

### 7.2 重试率监控

**指标定义**：
- **重试率** = 重试请求数 / 总请求数
- **目标值**：< 5%

**告警规则**：
- **P1**：重试率 > 10%（30 分钟内告警）
- **P2**：重试率 > 5%（1 小时内告警）

### 7.3 降级事件监控

**指标定义**：
- **WebRTC 降级率** = WebRTC → WebSocket 降级次数 / WebRTC 连接尝试次数
- **目标值**：< 10%

**告警规则**：
- **P2**：降级率 > 20%（1 小时内告警）
- **P3**：降级率 > 10%（4 小时内告警）

### 7.4 告警通知

**通知方式**：
- **P0/P1**：短信 + 邮件 + 钉钉/企业微信
- **P2**：邮件 + 钉钉/企业微信
- **P3**：邮件
