## 2. 技术栈选型

### 2.1 前端技术栈

**Web 端**：
- React 18 + TypeScript + Vite：主流技术栈，开发效率高
- Tailwind CSS：快速构建现代UI
- Zustand：轻量级状态管理
- Web Serial API：浏览器原生串口访问

**桌面端**：
- Electron（推荐）：代码复用率高，生态成熟
- Tauri（备选）：体积小、性能优，安装包仅10MB
- serialport：Node.js串口库

**移动端**：
- React Native（推荐）：与Web端共享逻辑，开发效率高
- react-native-usb-serialport：Android USB串口支持

---

### 2.2 后端技术栈

**Web框架**：
- Node.js 18 LTS + Express.js：成熟稳定，与前端技术栈一致
- WebSocket (ws)：实时通信（信令、数据中转）

**数据库**：
- PostgreSQL 14+：主数据库，存储用户、配置、项目、会话、测试库、Wiki等

**ORM**：
- Prisma（推荐）：类型安全、迁移方便

---

**注意**：当前版本未实现AI服务集成，计划在后续版本实现。

---

### 2.4 基础设施

- Docker + Kubernetes：容器化与编排
- Nginx：反向代理、负载均衡
- GitHub Actions：CI/CD
- Prometheus + Grafana：监控告警

## 4. 核心模块设计

### 4.1 前端模块结构

```
src/
```

## 5. 数据流架构

### 5.1 本地串口调试

```
硬件设备 → Web Serial API → serial.ts → React组件 → Zustand → UI渲染
```

### 5.2 远程协作（WebSocket中转）

```
发起者 → Web Serial API → WebSocket → 后端信令服务器 → WebSocket → 协作者 → UI显示
```

**流程说明**：
1. 发起者连接设备后创建会话，生成邀请码
2. 协作者通过邀请码加入会话
3. 双方通过WebSocket连接到信令服务器
4. 发起者的串口数据通过WebSocket转发给协作者
5. 协作者的发送数据通过WebSocket转发给发起者
6. 智能桥接模式下，系统自动检测设备状态并调整交互模式

## 6. 安全性设计

### 6.1 通用安全措施

- HTTPS/WSS强制加密（TLS 1.3）
- JWT Token认证
- CORS策略控制
- Rate Limiting限流
- SQL Injection防护
- XSS防护
- 密码bcrypt哈希
- 敏感字段AES-256加密

### 6.2 会话安全措施

**会话管理**：
- 邀请码唯一性验证
- 会话密码保护（可选）
- 会话过期时间控制
- 参与者数量限制

**权限控制**：
- 发送权控制（会话共享模式）
- 设备状态检测（智能桥接模式）
- 管理员权限验证

## 9. 监控与运维

**监控指标**：
- 性能：响应时间、吞吐量、错误率
- 可用性：服务可访问性、会话成功率、WebSocket连接数
- 业务：DAU/MAU、功能使用率、会话创建数

**告警级别**：
- P0：服务宕机、数据库故障
- P1：性能降级、WebSocket服务异常
- P2：错误率上升

**监控工具**：系统日志、错误日志、管理员后台监控面板
